## 持久化

例如执行一个set name youlin,Redis会把数据存到内存当中，如果杀掉进程或关闭电脑数据则会丢失，因此需定期写入磁盘，保存数据

### 持久化方式

RDB（快照）
在某一时刻保存dump.rdb文件生成快照

优点：恢复快
缺点：可能会丢失数据，例如我两点生成快照，两点四十读取，期间四十分钟数据会丢失

AOF(记流水账)

例如set name youlin,AOF也set name youlin写进去，全部记录，重启时重新执行一遍命令

优点：数据安全。
缺点：文件越来越大。

实际生产时RDB+AOF
原因：
RDB恢复快
AOF数据安全

## 过期策略

例如：SET code 123456 EX 60
问题来了，Redis如何知道过期？，假如有1000万Key，直接遍历cpu会爆炸
方式惰性删除
Redis不会主动删除，当用户访问时，发现过期才会删除，缺点，占内存
也因此Redis会采取定期删除，每隔一段实际随机抽查，发现过期删除

## 内存淘汰
Redis是内存数据库，内存有上限

### noeviction
默认策略之一
内存满不删，新写入直接报错

### LRU（最常见
最经典

### TTL淘汰
优先删除快过期的
